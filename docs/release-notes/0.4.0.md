# 0.4.0 — versionCode 8

Released 2026-09-09. The previous published build was at `versionCode 6`, so everything below is
new to users in this one.

---

## Play Console — "What's new"

388 of the 500 characters allowed. Written for the people reading it: no feature names, no jargon,
short sentences.

> Notices that come with a picture or a PDF now open properly. You can open, share, or save a copy
> of anything attached, and a link shows a small preview.
>
> If your code is ever stopped, your saved notices stay on this phone. The app now tells you what
> happened, shows your code for the helpdesk, and lets you check again or enter a new code.
>
> The code box adds the dash for you as you type.

## For the NGO staff — the console and sender

### Codes

- Every code now keeps a history: issued, printed, revoked, restored, released, renamed — with who
  did it and when. Sort by **Last change** to see recent activity, or press **history** on a row for
  the full list.
- New codes are easier to read aloud. They always contain two repeated characters — `SCCM-7VV7`,
  `AEE5-D1D6` — instead of seven unrelated ones.
- **Delete** removes a code that was generated but never used. A code somebody has activated must be
  **Released** first: deleting a live one would cut that phone off with no explanation anywhere.

### Printing

- Printing now covers only codes that are unused **and not yet printed**, so a second run does not
  reprint the whole batch.
- After the print dialog you are asked whether the slips came out. Yes marks them **Printed**; no
  leaves them for next time.
- Tick **include already printed** to reprint a lost slip.
- Slips carry a small QR to the Play listing, for anyone who has not installed the app yet.

### Sending

- Every notice records who sent it, shown in the history list. Automatic sends from the feed show as
  `poller`.
- Revoking a code reaches the phone in about a minute instead of a day — once `Revoker.gs` and its
  trigger are installed.

### What changed on the phones

- Being cut off no longer hides somebody's notices. They keep them, with an explanation, their code
  for the helpdesk, and a way back in.
- Restoring a code brings the phone back on its own. No new slip needed.

## Technical, for the record

- **Entitlement checks moved off the message path** into `ActivationRefreshWorker`. A broadcast to
  400 phones no longer opens ~400 database sockets within seconds, against a Spark cap of 100 — the
  check used to stop working during exactly the event it exists for. See `docs/decisions.md`.
- **Revocation suspends the claim rather than surrendering it**, which is what makes Restore work at
  all. Previously the device threw away its code and UID, and the rules refuse to re-claim a code
  that still carries `usedBy`, so a revoked phone could never return by any route.
- **A revoke is pushed** as a data-only `{"type":"revoke","code":…}` broadcast and applied on
  receipt; the daily verification is the fallback for a phone that was switched off.
- **New RTDB nodes:** `/audit` (append-only, kept even when a code is deleted) and `/revokeQueue`.
  No security-rules change — both inherit deny-by-default, and neither adds a field to `/codes`,
  where a new sibling would break the app's claim write.
- **Room schema at version 3.**
- 84 JVM unit tests; 44 console tests (`runConsoleTests`).

### Not in the bundle

The console and sender changes are pasted by hand:

1. Console — `Code.gs`, `Index.html`, `Tests.gs`; run `runConsoleTests`, expect `All 44 passed.`
2. Sender — `Code.gs`, `Tests.gs`, and the new `Revoker.gs`; run `revokerDryRun()`, then
   `revokerInstallTrigger()`.
3. Sender needs a **New version** deployment, because `doPost` was removed. `Revoker.gs` is a
   trigger and needs no redeploy.

Until the trigger is installed, revocation still works — it is recorded in `/codes` and `/audit`,
and phones act on it at their next daily check. Only the speed depends on it.

### Known and deliberate

- **R8 is off** (`optimization { enable false }` in `app/build.gradle`), which is what Play's
  optimization score reflects. Turning it on is a materially different artifact and wants its own
  release with a device pass — `ActivationRefreshWorker` is instantiated reflectively by
  WorkManager, and a failure there would be silent.
- **Closed testing shares the production topic.** There is no separate test audience; sends reach
  every subscriber.
