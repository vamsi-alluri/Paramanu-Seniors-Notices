# 0.5.0 — versionCode 9

Built 2026-09-13. **A breaking release.** It needs the new database shape, security rules and
console and sender scripts in place first (SYSTEM.md §10, "Move to dispensaries"). Phones still on
0.4.0 stop receiving notices, pushed revokes and banner changes until they update.

## Play Console — "What's new"

415 of the 500 characters allowed. Written for the people reading it: no feature names, no jargon,
short sentences.

> The time on each notification is now when the notice was sent, so it matches everyone else's.
>
> The dispensary timings at the top of the app update by themselves soon after they change.
>
> Settings shows what your dispensary sends. The daily open and closed messages have ended.
>
> If your code is stopped and turned back on, notices start again without opening the app.
>

## For the NGO staff — the console and sender

### Codes: new names

| Before | Now |
|---|---|
| Revoke | **Disable** |
| Restore | **Enable** |
| Release | **Unlink phone** |
| Note | **Edit note** |
| Delete | **Delete code** |
| Generate | **Generate 10** (shows the number it will make) |

Only the words changed. The history of every code carries on, shown with the new names.

### Holders

- Each code can record who it was given to: **name** (required), **CHSS number** and **telephone**.
  Three new columns in the table, and each can be sorted.
- **Add holder**, **Edit holder**, **Move holder** (to a new code the dispensary has issued) and
  **Remove holder**. Every change is kept in the row's history, showing what it was before.
- **Remove holder** puts the code **On hold**: its phone stops within a minute and every button on the
  code is locked. A mistake is undone from **Removed holders**, below the codes table, for 30 days.
  **Restore holder** puts the code back exactly as it was — if it was Disabled, it stays Disabled.
- After 30 days a removed holder is erased for good and the code goes back to **Unused**.
- A code with a holder, a phone, or On hold cannot be deleted. Move the holder to their new code first.

### Finding a code

- A **search box** above the table finds a code with or without its dash, a name, a CHSS number,
  telephone digits, or note text.
- The **Status** heading has a filter, for example to show only Disabled codes.
- The number, note and **Generate** button sit together in one outlined box.

### Printing

- Works as before, with one difference: **Unlink phone no longer puts a slip back on the print
  sheet**. The slip still belongs to its holder.
- Printing can be switched off in Script Properties (`PRINTING_ENABLED = false`). The Print button
  then stays on screen, greyed out, with a line saying why.

### Banner

- Phones pick up a saved banner within about a minute, even with the app open.
- A banner can hold less than before, because it now travels inside the message to every phone.
  Saving one that is too long says so, and by how much.

### Removed

- **Daily open and closed**: the section in the console, the counter QR page in the sender, and the
  switch in the app. Nothing sends them any more.

### What changed on the phones

- Enabling a code, or restoring its holder, brings the phone back within about a minute, without
  anyone opening the app.
- The tray notification shows the time the notice was sent, not when that phone happened to receive
  it. Two phones now show the same time for the same notice.
- **Reset this app** is gone from Settings. Somebody whose code was stopped can still **Enter a new
  code**, and keeps their notices.

## Technical, for the record

- **Dispensaries.** `/dispensaries/{id}` holds `name`, `topics` and the banner under `info`. Each code
  carries `dispensary`, written by the console from `DISPENSARY_ID`. The one dispensary today is
  **BARC Vashi Dispensary** (`barc-vashi`), seeded from `docs/dispensary-barc-vashi.json`. Settings is
  drawn from the dispensary's topics; `Subscription` is gone. See `docs/decisions.md`.
- **Notices carry `topic`.** The phone drops a notice on a topic its dispensary does not offer or its
  user has switched off, and picks the channel from the topic's importance. Channels are one per
  importance (`notices_default`, `notices_low` created on first use, `notices_testing`), never per
  topic. The sender and poller send to the dispensary's first topic by `order`.
- **Subscriptions are reconciled.** The phone remembers what it subscribed to and unsubscribes a topic
  its dispensary no longer offers. A revoked phone no longer quietly resubscribes to notice topics on
  every launch — an existing bug, fixed.
- **Control topic `control-v1`.** Revoke, resume and banner changes, each stamped with `at`; a phone
  ignores a stamp no newer than the last it applied, because FCM does not promise order. Held while
  revoked, so a resume can reach the phone. Banners name their dispensary and carry their html inside
  the message, capped at 3500 UTF-8 bytes. The console queues to `/controlQueue`; `Control.gs`
  replaces `Revoker.gs`.
- **Holders** live at `/holders/{id}` with their own history, invisible to phones. `/audit` records
  holder events by id only, so the 30-day purge genuinely removes a person. **On hold** is derived
  from the audit, like Printed — no new field on `/codes`.
- **Security rules changed:** `/dispensaries/{id}` readable by signed-in users, `/codes/{CODE}/
  dispensary` protected from the app, the `/info` rule dropped.
- **Backward compatibility deliberately removed** for closed testing: no dual-publish of revoke to
  `notices-v1`, no draining of `/revokeQueue`, no unstamped control messages, no `status-v1`.
- **Sender bug fixed:** the bodies of `statusMessage_` and `defaultStatusMessage_` were swapped, so
  the default recursed until the stack ran out and wording edited in the console was never sent. Moot
  now that the daily status is removed, but it was aborting `runAllTests`.
- **Room schema unchanged at version 3.**
- 108 JVM unit tests; 100 console tests (`runConsoleTests`).

### Not in the bundle

The database and scripts are changed by hand, in this order (full detail in SYSTEM.md §10):

1. Import `docs/dispensary-barc-vashi.json` at `/dispensaries/barc-vashi` — select that node, never the
   root.
2. Console: set `DISPENSARY_ID = barc-vashi`, paste `Code.gs`, `Index.html`, `Tests.gs`. Run
   `migrateToDispensariesDryRun()`, then `migrateToDispensaries()`.
3. `firebase deploy --only database`.
4. Delete `/info` and `/status` in the data viewer.
5. Console: new version; `runConsoleTests`, expect `All 100 passed.`; `purgeInstallTrigger()` once.
6. Sender: set `DISPENSARY_ID = barc-vashi`; paste `Code.gs`, `Index.html`, `Poller.gs`, `Tests.gs`
   and the new `Control.gs`; delete `Status.html` and `Revoker.gs`; `controlInstallTrigger()`; new
   version; `runAllTests` with nobody using the console.
7. Upload this build. Then delete the migration section from the console's `Code.gs`.

### Known and deliberate

- **Testers on 0.4.0 are fixed by hand**, not by compatibility code. Their phones keep a dangling
  `status-v1` subscription that nothing sends to, and a "Daily open and closed" entry in Android's
  notification settings until the app's data is cleared.
- **R8 is still off.** Unchanged from 0.4.0, and still wants its own release with a device pass.
- **Closed testing shares the production topic.** Sends reach every subscriber.
- **Holder details are stored by the console**, not collected by the app. The privacy policy review
  before production should still say so.
